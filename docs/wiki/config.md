# Configuration Reference

[← Index](INDEX.md) | [Daemon](daemon.md) | [Quattro Plugin](quattro.md)

Configuration lives at `~/.config/omarchy10k/config.toml`. All keys are optional — missing keys fall back to compiled defaults. The daemon embeds `config/default.toml` via `include_str!` and merges user config on top via serde's `#[serde(default)]`.

## Config File Locations

| Path | Purpose |
|------|---------|
| `~/.config/omarchy10k/config.toml` | User configuration (editable) |
| `config/default.toml` | Defaults (embedded in daemon binary) |
| `~/.local/state/omarchy/current/theme/colors.toml` | Generated by theme system (not user-editable) |

Path resolution uses the `directories` crate with XDG fallback to `$HOME/.config/omarchy10k`.

## `[plugins]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | string[] | `[]` | installed plugin names | Yes | Enabled segment plugins from `~/.config/omarchy10k/plugins/<name>/` (plugin.toml: env-tier and command-tier segments). Managed by `omarchy10k plugin enable/disable`; the daemon registry reloads on config change. Added in v0.4.1. |

Built-in segment catalog (v0.4.1, all default-off): `package_version` (cwd manifest scan), `dir_writable` (cached write probe), `aws_profile` (env), `docker_context` (env + async), `kubectl_context` (async), `terraform_workspace` (stat-gated async), `vpn` (sysfs tun/tap/wg), `gcloud_project` (env + async).

## Project profiles (`.o10k.toml`)

A repo can carry its own prompt: a `.o10k.toml` file at the project root (or any ancestor dir below `$HOME`) applies a display patch while you work in that project. Detection walks upward from the prompt cwd and stops at the first profile file OR `.git` boundary (profiles never leak across repos); `$HOME` itself is never considered.

The file is **untrusted input** (it ships with cloned repos), so it is allowlisted to display keys only: `style`, `prompt`, `segments` (display flags/icons/glyph names), `theme`, `frame`. Any other top-level key (`daemon`, `env`, `notifications`, `git`, unknown) rejects the whole file with a named error in the daemon log, and the prompt renders with base config — it can never fail or alter daemon behavior. State is cached (30s TTL, bounded 512 entries).

```toml
# .o10k.toml — example: quiet production prompt
[segments]
git = { enabled = false }
time = { enabled = true }
```

Merge order at render: base config → transient Look → project profile → ephemeral preview patch (Studio/wizard wins). Added in v0.4.1. The wizard's finish step can write this file.

## `[shell.layer]`

Shell-layer policy, resolved by `omarchy10k init bash` and baked into the emitted adapter (no runtime reads). Added in v0.4.1 (CLI-side only; the daemon ignores it).

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `policy` | string | `"extend"` | `extend`, `defer`, `own`, `off` | Yes | Global claim policy. `extend`: extend platform definitions where an extender exists, defer otherwise; `defer`: platform items always win; `own`: o10k redefines; `off`: o10k defines nothing. User-defined items are never touched under any policy. |
| `overrides` | map | — | claim name → policy | Yes | Per-claim override of the global policy, e.g. `ls = "own"`, `grep = "defer"`. |

Claim inventory and platform signatures: `omarchy10k layer` (or `--json`). Prompt ownership handoff (starship/Ghostty unhooking) runs once at adapter init; `doctor` reports displaced hooks and any legacy `~/.bashrc` surgery that is safe to remove.

## Quick actions (scripts)

Executable user scripts in `~/.config/omarchy10k/scripts/*.sh` are quick actions: `omarchy10k script list` prints JSON `{dir, scripts:[{name,path}]}`; `omarchy10k script run <name>` executes via the daemon (30s hard timeout, per-call `timeout_secs` override in the `script_run` payload), with local-exec fallback when no daemon is reachable. Added in v0.4.1.

## `[theme]`

Controls color source.

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `source` | string | `"omarchy"` | `omarchy`, `custom`, `hybrid`, `terminal` | Yes | Color palette source. `omarchy` reads from theme system. `custom` uses only `[theme.custom]`. `hybrid` merges both. `terminal` resolves from the rendered terminal palette file (ghostty.conf in the theme state dir): background/foreground direct, accent=palette 4, muted=palette 8, red..cyan=palette 1–6, orange=11, bright=15; falls back to defaults when the file or entries are missing. `[theme.custom]` overrides still win. Custom overrides not re-applied on `reload_theme`. |

| `gradient` | string | `"auto"` | `auto`, `off`, `full` | Yes | How wide a hue sweep the palette's gradient ramp takes from the accent. `auto` = 38°, `full` = 64°, both rotated in OKLCH so the ramp stays inside the accent's own hue family; `off` collapses the ramp to a flat accent and outranks `ramp`. |
| `ramp` | array | — | two hex strings | Yes | Art-directed ramp override, start → end. Wins over `gradient` unless that is `off`. Curated palettes that ship one are also matched by accent, so a config written before this key still gets its art direction. |

### The gradient ramp

One ramp per palette, used everywhere a gradient appears: the `gradient` style
preset's segment fills and `[style.frame] gap_gradient = "full"`. They read the
same two colors, so they cannot disagree.

The far end used to be an ANSI slot chosen by `accent.b >= accent.r` — the
`magenta` role for cool accents, `cyan` for warm ones. That comparison is seven
bytes of red apart for Synthwave's `#d53bce`, so a palette sold as "purple all
the way down" rendered a purple → `#00b0b1` teal rule. The far end is now the
accent rotated in OKLCH at constant lightness and chroma, which keeps hue in
family, leaves greyscale accents grey (zero chroma makes the rotation a no-op),
and preserves the contrast work in `palette_derive`.

A patch that sets `[theme.custom]` replaces `custom` and `ramp` wholesale
rather than merging, so switching palettes cannot leave the previous one's
ramp behind.

## `[looks.<name>]`

Named Looks: a patch bundle over the config plus a palette directive. 52
curated Looks are compiled into the daemon (see `omarchy10k look list` for
the full set); user entries defined in `config.toml` shadow a curated Look of
the same name. Added in protocol 0.5 / crate 0.4.0.

| Key | Type | Default | Values | Description |
|-----|------|---------|--------|-------------|
| `label` | string | `""` | any | Display name in the panel/gallery. Empty label falls back to the Look name. |
| `palette` | string | `"keep"` | `keep`, `theme`, or curated palette key (`tokyo-night`, `catppuccin`, `gruvbox`, `nord`, `dracula`, `rose-pine`, `everforest`, `kanagawa`) | Resolved at apply time. `keep` leaves the current theme untouched; `theme` re-sources from the Omarchy theme system (`theme.source = "omarchy"`); a curated palette key merges that palette into `[theme.custom]` with `source = "hybrid"`. Unknown keys are ignored. |
| `patch` | table | `{}` | `config_set`-shaped patch | Merged onto the config at apply time with the same atomic single-patch merge as `config_set`. Top-level config keys only. A `glyphs` shortcut subtable is expanded first (see below). |

`[looks.<name>.patch] glyphs` shortcuts: `os_icon` → `segments.os.icon`,
`character` → `segments.character.success`/`error`/`transient`,
`git_branch_icon` → `git.branch_icon`.

Example:
```toml
[looks.mine]
label = "My Look"
palette = "tokyo-night"

[looks.mine.patch]
style = { preset = "lean", separators = { shape = "round" } }
frame = { enabled = false }
glyphs = { character = "lambda", git_branch_icon = "nerd" }
```

Applied via the CLI (`omarchy10k look list`, `look apply <name> [--transient]`,
`look save <name> [label]`) or the protocol control verbs `looks`,
`looks_apply` (`transient` = try mode: in-memory only, reverted by
`reload_config`), `looks_save`, plus `palettes` (curated palette list) and
`defaults` (compiled-in default config). The `preview` message accepts a
`look` override for dry-run renders used by the gallery overlay.

## `[segments.dir_writable]`

Write-permission warning segment (Tier D, v0.4.1, default-off): renders a red lock glyph only when the cwd is **not** writable. The check is a real create/delete probe (`.o10k-writetest-<pid>` file, immediately removed) rather than metadata permission bits, since bits miss ACLs, read-only mounts, and other-user ownership. Cached per cwd with a 10 s TTL. Hidden below 40 columns (hardcoded); priority 6 (survives heavy compression).

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `false` | — | Yes | Warn (red lock) when the cwd is not writable; silent when it is. |
| `icon` | string | Nerd Font glyph U+F023 (lock) | Any string | Yes | Glyph shown when the probe fails. |

## Hot Reload

The daemon watches two filesystem paths for changes:

| Path | Trigger | Effect |
|------|---------|--------|
| `~/.config/omarchy10k/config.toml` | File write | `DaemonState::reload_config()` — re-reads TOML, updates `RwLock<Config>` |
| `~/.local/state/omarchy/current/theme/colors.toml` | File write | `DaemonState::reload_theme()` — re-reads palette |

Reload can also be triggered via:
- CLI: `omarchy10k reload`
- Daemon protocol: `{"command":"reload_config"}` or `{"command":"reload_theme"}`
- Quattro panel: Reload Config button, or automatic after config save

### `[terminal.cursor_shape]`

Cursor shape per vi mode, via DECSCUSR (`CSI Ps SP q`). The sequence is
prepended to the prompt, so it lands before the user types.

| Key | Type | Default | Notes |
|-----|------|---------|-------|
| `enabled` | bool | `false` | Off by default: installing a prompt must not silently override a cursor style already set in the terminal's own config |
| `insert` | int | `6` | vi INSERT, and every non-vi shell. 5 = blinking bar, 6 = steady bar |
| `normal` | int | `2` | vi NORMAL. 1 = blinking block, 2 = steady block |
| `replace` | int | `4` | vi REPLACE. 3 = blinking underline, 4 = steady underline |

Defaults are the steady shapes: a blinking cursor competes with the prompt
for attention, and Omarchy's own Ghostty config already asks for
`cursor:steady`.

Not gated on a terminal capability. DECSCUSR predates every terminal in the
catalog and all of them honour it; one that does not simply ignores the
sequence. Parameters outside 0-6 are undefined by DECSCUSR, so a bad value
emits nothing rather than writing garbage at the terminal.

The mode comes from bash's `KEYMAP` over the env channel. `vi`, `vi-command`,
`vi-move` and `vicmd` map to `normal`; `vi-replace` to `replace`; everything
else — including emacs mode and a shell with no vi mode at all — to `insert`.
