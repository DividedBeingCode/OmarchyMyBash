# Configuration Reference

[← Index](INDEX.md) | [Daemon](daemon.md) | [Quattro Plugin](quattro.md)

Configuration lives at `~/.config/omarchy10k/config.toml`. All keys are optional — missing keys fall back to compiled defaults. The daemon embeds `config/default.toml` via `include_str!` and merges user config on top via serde's `#[serde(default)]`.

## Config File Locations

| Path | Purpose |
|------|---------|
| `~/.config/omarchy10k/config.toml` | User configuration (editable) |
| `config/default.toml` | Defaults (embedded in daemon binary) |
| `~/.local/state/omarchy/current/theme/colors.toml` | Generated by theme system (not user-editable) |

Path resolution uses the `directories` crate with XDG fallback to `$HOME/.config/omarchy10k`.

## `[prompt]`

Controls prompt structure and behavior.

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `layout` | string | `"omarchy"` | `omarchy`, `minimal`, `powerline`, `classic`, `pure`, `dense` | No | Prompt layout preset. Currently ignored — always uses omarchy layout. |
| `transient` | bool | `true` | — | Yes | Replace previous prompts with a minimal `❯` after command execution. Requires ble.sh for full effect. |
| `newline` | bool | `true` | — | Yes | Two-line prompt (segments on line 1, character on line 2) vs one-line. |
| `right_prompt` | bool | `true` | — | No | Enable right-aligned prompt. Currently `right` is always `None` in responses. |

## `[theme]`

Controls color source.

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `source` | string | `"omarchy"` | `omarchy`, `custom`, `hybrid`, `terminal` | Partial | Color palette source. `omarchy` reads from theme system. `custom` uses only `[theme.custom]`. `hybrid` merges both. `terminal` falls back to defaults. Custom overrides not re-applied on `reload_theme`. |

### `[theme.custom]`

Optional color overrides for `custom` and `hybrid` modes. All values are hex color strings.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `accent` | string | — | Primary highlight color |
| `foreground` | string | — | Default text color |
| `muted` | string | — | De-emphasized text |
| `background` | string | — | Background color |
| `red` | string | — | Error/destructive |
| `green` | string | — | Success |
| `yellow` | string | — | Warning |
| `blue` | string | — | Info |

Example:
```toml
[theme]
source = "custom"

[theme.custom]
accent = "#bb9af7"
foreground = "#c0caf5"
muted = "#565f89"
background = "#1a1b26"
red = "#f7768e"
green = "#9ece6a"
yellow = "#e0af68"
blue = "#7aa2f7"
```

## `[directory]`

Controls working directory segment display.

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `strategy` | string | `"smart"` | `smart`, `full`, `truncate` | No | Path display strategy. Always uses smart truncation. |
| `max_length` | int | `40` | — | Yes | Maximum path display length in characters. |
| `repo_root_style` | string | `"bold"` | — | No | Style for git repo root directory. Always bold. |

## `[git]`

Controls git integration.

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | Yes | Toggle git segment entirely. |
| `mode` | string | `"adaptive"` | `hidden`, `compact`, `expanded`, `adaptive` | Yes | Git segment detail level. `adaptive` shows expanded when dirty, compact when clean. |
| `stale_display` | bool | `true` | — | No | Show grayed-out stale state while git refreshes. `stale` field is never set true. |
| `max_threads` | int | `4` | — | No | Parallelism for git queries. Single-threaded in practice. |

## `[segments.os]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | No | No OS segment exists yet. |
| `icon` | string | `"arch"` | `arch`, `linux`, `omarchy`, `custom`, `none` | No | OS icon glyph. |

## `[segments.exit_status]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | Yes | Show segment for non-zero exit codes. |
| `show_signal_name` | bool | `true` | — | Yes | Show human-readable signal names (SIGKILL) vs raw codes (137). |

## `[segments.command_duration]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | Yes | Show command execution time. |
| `show_above_ms` | int | `1500` | — | Yes | Minimum milliseconds to display duration. |

## `[segments.jobs]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | No | Background jobs count. `jobs` field is in the protocol but no segment renders it. |

## `[segments.ssh]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `enabled` | bool | `true` | — | No | SSH indicator. `in_ssh` is detected in render.rs but no segment uses it. |
| `show` | string | `"auto"` | `auto`, `always`, `never` | No | When to show SSH indicator. |

## `[segments.character]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `success` | string | `"❯"` | Any string | Yes | Prompt character for successful commands. |
| `error` | string | `"❯"` | Any string | Partial | Prompt character for failed commands. Transient prompt ignores this and hardcodes `❯`. |

## `[daemon]`

| Key | Type | Default | Values | Implemented | Description |
|-----|------|---------|--------|-------------|-------------|
| `socket` | string | `"auto"` | `auto` or absolute path | No | Socket path. `auto` is always used; value is computed from `XDG_RUNTIME_DIR` + PID. |
| `log_level` | string | `"warn"` | `trace`, `debug`, `info`, `warn`, `error` | Yes | Tracing subscriber env filter level. |

## Hot Reload

The daemon watches two filesystem paths for changes:

| Path | Trigger | Effect |
|------|---------|--------|
| `~/.config/omarchy10k/config.toml` | File write | `DaemonState::reload_config()` — re-reads TOML, updates `RwLock<Config>` |
| `~/.local/state/omarchy/current/theme/colors.toml` | File write | `DaemonState::reload_theme()` — re-reads palette |

Reload can also be triggered via:
- CLI: `omarchy10k reload`
- Daemon protocol: `{"command":"reload_config"}` or `{"command":"reload_theme"}`
- Quattro panel: Reload Config button, or automatic after config save
